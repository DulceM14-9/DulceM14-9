01 · Orientación

El mapa del tema

Recorre el ecosistema desde los fundamentos hasta la aplicación real. Cada pieza cumple una función y tiene límites propios.

⌘
Fundamentos

Aprender patrones

Machine Learning y Deep Learning detectan regularidades en datos para clasificar, predecir o reconocer patrones complejos.

Aa
Lenguaje

Interpretar y generar

El PLN trabaja con lenguaje humano. Los LLM resumen, redactan, clasifican, extraen información y apoyan programación.

◉
Percepción

Analizar imágenes

La visión artificial detecta objetos, defectos y eventos en imágenes o video, por ejemplo en inspección de calidad.

✦
Generación

Crear contenido

La IA generativa produce texto, imágenes, audio o código; la fluidez no garantiza que la salida sea verdadera.

↗
Acción

Conectar herramientas

Los agentes pueden usar herramientas y actuar sobre sistemas. La autonomía exige límites, permisos y controles adicionales.

◇
Sistema completo

Convertir IA en valor

Datos, infraestructura, personas, procesos, integración, gobernanza y estrategia condicionan el resultado empresarial.

Idea clave: el valor empresarial no equivale a la calidad del modelo solamente. Depende de cómo se conecta con el trabajo real y de cómo se mide, supervisa y mejora.
02 · Tecnologías

Elige la herramienta correcta

Selecciona una tecnología para ver cómo funciona, qué problemas resuelve y qué precauciones conviene considerar.

Machine Learning · Aprender de ejemplos

Los algoritmos ajustan patrones a partir de datos para producir una predicción o clasificación.

Aplicaciones

Pronóstico de demanda, riesgo crediticio, detección de fraude y mantenimiento predictivo.

Ventaja

Puede detectar relaciones difíciles de expresar mediante reglas manuales.

Precaución

Datos sesgados, cambios del entorno o una métrica mal elegida pueden degradar resultados.

Deep Learning · Representaciones complejas

Usa redes neuronales con múltiples capas para aprender representaciones de datos complejos.

Aplicaciones

Reconocimiento de voz, traducción, análisis visual y modelos de lenguaje.

Ventaja

Puede lograr alto rendimiento con datos, cómputo y evaluación adecuados.

Precaución

Puede requerir muchos recursos y experiencia; explicar los resultados puede ser difícil.

Procesamiento del lenguaje natural · Trabajar con palabras

Permite analizar, transformar y generar lenguaje humano según una tarea.

Aplicaciones

Clasificar solicitudes, resumir informes, extraer cláusulas, traducir y buscar documentos.

Ventaja

Reduce trabajo textual repetitivo y facilita el acceso a información.

Precaución

Ambigüedad, contexto cultural y jerga interna pueden causar errores.

Visión artificial · Interpretar lo visual

Procesa imágenes o video para identificar objetos, defectos, escenas o patrones.

Aplicaciones

Inspección de productos, seguridad industrial y conteo visual.

Ventaja

Puede revisar grandes volúmenes visuales de forma consistente.

Precaución

Iluminación, ángulo, resolución y ambiente afectan el desempeño.

IA generativa · Crear y transformar

Genera contenido a partir de patrones aprendidos e instrucciones.

Aplicaciones

Borradores, prototipos, síntesis, asistencia de código y búsqueda conversacional.

Ventaja

Flexibilidad para múltiples tareas mediante instrucciones y contexto.

Precaución

Puede inventar datos, omitir matices, reproducir sesgos o exponer información si se configura mal.

Agentes · Del contenido a la acción

Combinan un modelo con herramientas, instrucciones y un ciclo de decisión para avanzar hacia un objetivo.

Aplicaciones

Clasificar tickets, consultar sistemas internos y coordinar flujos autorizados.

Ventaja

Conecta tareas que antes exigían cambiar entre aplicaciones.

Precaución

Errores, instrucciones maliciosas o permisos excesivos pueden causar acciones no deseadas.

03 · Dentro del modelo

¿Cómo funciona un LLM?

Conceptos prácticos para diseñar, evaluar y desplegar modelos de lenguaje.

▦

Tokens

Unidades de texto que el modelo procesa. Una palabra puede dividirse en una o varias piezas según el tokenizador.

⚙

Parámetros

Valores numéricos ajustados durante el entrenamiento. Los patrones se representan de forma distribuida, no como una ficha por hecho.

↻

Entrenamiento

Aprendizaje de patrones a partir de datos, mediante objetivos y ajustes matemáticos definidos por el sistema.

→

Inferencia

Uso del modelo entrenado para calcular una salida a partir de una entrada y un contexto.

Lo que puede hacer bien

  • Resumir y transformar texto.
  • Clasificar y extraer información.
  • Generar borradores, traducciones y código.
  • Responder con contexto y fuentes suministradas.

Lo que no debes asumir

  • Que cada respuesta es verdadera.
  • Que siempre está actualizado.
  • Que comprende como una persona.
  • Que una respuesta convincente está verificada.
Confabulación o “alucinación”: un modelo puede producir una respuesta falsa o no sustentada con apariencia de seguridad. Para tareas importantes, verifica fuentes, limita el alcance y diseña pruebas explícitas.
04 · Fuentes de verdad

LLM ≠ base de datos

Ambos pueden trabajar juntos, pero no cumplen la misma función.

LLM

Representaciones aprendidas

Los patrones están distribuidos entre parámetros. El modelo genera respuestas a partir de entrada y contexto; no es un registro estructurado de hechos verificables.

  • Útil para lenguaje e interfaces conversacionales.
  • Puede equivocarse o estar desactualizado.
  • No ofrece por sí solo garantías transaccionales.
Base de datos

Registros explícitos y actualizables

Guarda información en estructuras diseñadas para consultar, actualizar, mantener integridad y aplicar permisos.

  • Útil para inventario, pedidos, clientes y registros financieros.
  • Refleja cambios mediante procesos controlados.
  • Puede ofrecer consistencia, auditoría y consulta.
Ejemplo: para saber cuántas unidades quedan, la fuente de verdad debe ser el sistema de inventario. El LLM puede consultar y explicar el dato, no inventarlo ni sustituir el registro operativo.

Antes de desplegar

Define problema, usuario, línea base, datos disponibles, riesgos y métrica de éxito.

Durante el despliegue

Controla acceso, latencia, costos, privacidad, versiones, errores y permisos de herramientas.

Después del despliegue

Monitorea calidad, cambios de datos, incidentes, satisfacción, ahorro y efectos no previstos.

Asistente vs. agente

Asistente

Genera información, sugerencias o borradores; una persona decide qué hacer.

Ejemplo: redacta una respuesta al cliente para que el equipo la revise.

Agente

Puede usar herramientas y ejecutar pasos dentro de permisos concedidos.

Ejemplo: consulta un pedido y actualiza su estado mediante una API autorizada.

Principio de mínimo privilegio: concede a cada agente solo los permisos necesarios. Las acciones de alto impacto necesitan validaciones, límites, registros y, cuando corresponda, aprobación humana.
07 · Empresa y sociedad

Impacto: oportunidades y tensiones

La IA puede cambiar tareas y procesos, pero la adopción no garantiza rentabilidad automática.

⏱

Productividad

Puede reducir tiempo en ciertas tareas, mejorar el acceso a información y apoyar procesos. El efecto varía según tarea, experiencia y contexto.

♧

Trabajo y habilidades

La exposición no equivale a automatización total. Muchos puestos combinan tareas automatizables y otras que requieren juicio y responsabilidad humana.

⚡

Energía e infraestructura

Los centros de datos requieren electricidad y cómputo. La eficiencia por tarea debe analizarse junto con el crecimiento de la demanda total.

08 · Confianza

Gobernanza que se puede ejecutar

Los principios éticos se vuelven útiles cuando se traducen en responsabilidades, mecanismos técnicos y procedimientos.

Transparencia

Informar cuándo se usa IA, qué fuentes alimentan la respuesta y cuáles son sus límites.

Responsabilidad

Asignar responsables, documentar decisiones y mantener rutas de revisión.

Privacidad y seguridad

Minimizar datos, aplicar permisos, proteger secretos y evaluar amenazas antes de conectar herramientas.

Supervisión humana

Definir cuándo una persona valida, corrige, detiene o revierte una acción.

¿Qué significa trazabilidad?

Poder reconstruir qué versión de modelo, documentos, configuración y herramientas intervinieron en una respuesta o acción, dentro de límites razonables de privacidad y seguridad.

¿Cómo se evalúa un sistema antes de lanzarlo?

Con casos representativos, casos límite y pruebas adversariales; métricas de calidad y seguridad; comparación con una línea base; y criterios explícitos para detener el despliegue si no cumple.

¿Qué ocurre si el sistema falla?

Debe existir un modo seguro, una ruta para retirar permisos y escalar a una persona, registro de incidentes, recuperación del servicio y aprendizaje del fallo.

09 · Ventaja competitiva

Mismo modelo, distinto resultado

La diferencia suele estar en los activos complementarios y la ejecución, no solo en el nombre del modelo.

02 · InfraestructuraIntegración, confiabilidad, costo, latencia y escalabilidad.
03 · Personas y procesosHabilidades, rediseño del trabajo, adopción y gestión del cambio.
04 · Gobernanza y estrategiaObjetivos medibles, controles, responsabilidades y mejora continua.
Modelo mental: el modelo es el motor; los datos son parte del combustible; la infraestructura es el vehículo; las personas conducen; los procesos son la ruta; la gobernanza establece reglas y la estrategia define el destino.

12 · Ingeniería de Prompt

Diseña instrucciones mejores

Un buen prompt reduce ambigüedad: define objetivo, contexto, audiencia, restricciones y formato de salida.

Diagnóstico de estructura

Escribe un prompt y pulsa “Evaluar estructura”. Es una guía heurística, no una calificación científica.

Plantilla reutilizable: “Actúa como [rol]. Necesito [objetivo] para [audiencia/contexto]. Considera [alcance y restricciones]. Usa [fuentes/evidencia]. Entrega el resultado en [formato]. Evalúa con [criterios] y señala incertidumbres, límites y supuestos.”
13 · Síntesis

Qué conviene recordar

Una visión profesional comienza por el problema y termina con resultados medibles, no con la elección de un modelo por moda.

Conclusiones esenciales

  • La IA transforma tareas y procesos; no implica automáticamente reemplazo total del trabajo.
  • Los LLM generan lenguaje útil, pero pueden equivocarse.
  • RAG mejora el acceso a información, no garantiza exactitud.
  • Los agentes necesitan controles proporcionales a su autonomía.
  • La calidad del sistema incluye datos, integración, personas, procesos y gobernanza.

Preguntas antes de desplegar

  • ¿Qué problema medible resuelve?
  • ¿Cuál es la fuente de verdad?
  • ¿Qué errores son aceptables y cuáles no?
  • ¿Qué datos puede ver y qué acciones puede ejecutar?
  • ¿Cómo se mide el beneficio neto y quién responde por los resultados?
